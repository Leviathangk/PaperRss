# PaperRss 构建原则

本文档是 PaperRss 项目规则入口；专项流程仅在对应任务触发时读取。`trigger: always_on` 是兼容工具的元数据；实际读取由根目录 `AGENTS.md` / `CLAUDE.md` 的明确指针触发，不依赖规则目录自动发现。

## 核心文档与规则

- 当前 `.agents/rules/principle.md` 文档为全局唯一核心规则文档入口。
- `.agents/docs/*` 下的文档是专项流程。
- `documents/` 是调研、设计与历史归档，不是规则入口；任务明确引用或实现需要历史依据时才读取。
- 每个任务开始时读取核心规则；同一任务中已读且未变化的内容直接复用。涉及领域术语或架构决策时按需读取 [领域文档使用说明](../docs/domain.md)，不为了启动任务创建 CONTEXT 或 ADR。

## 对话风格

- 避免空话，保持回答清晰、明了，优先采用具体行为和小的示例说明，而不是抽象概述、密集术语
- 先说明结论、已做的更改和依据；有分歧时直接说明理由，不要求固定的同意或反对话术。
- 解释非平凡的设计和问题时，请按以下结构说明：问题、具体示例或简短跟踪，然后解决方案。说明解决方案为何必要，并将其与可选的复杂性区分开来。

## 任务范围与执行效率

- 以本轮需求和验收目标为边界，完成必要修复；额外重构、全仓审计和持续优化仅在用户要求或解决当前问题确有必要时开展。
- 先定位相关入口、实现和测试，按依赖扩展阅读；搜索限定目录或符号，优先读取命中片段，复用已读且未变化的内容。
- 小任务优先单 Agent；可独立且能节省时间的子任务可并行委派，明确各自文件或职责、共享工作区限制，由主 Agent 整合。不得回滚其他人的变更；相互依赖的修改顺序执行。
- 常规构建和测试完整日志由统一入口写入 `build/reports/`（保留 30 天）；独立 WebKit 探针也需保存完整输出到该目录。上下文优先读取退出码、结果摘要和失败上下文，信息不足再扩大读取，保留原始退出码，不能用日志截断掩盖失败。
- 相同失败连续两次且没有新证据时，改用针对性诊断，避免机械重试。必要验证通过后交付；发现新问题或相关代码变化时才继续验证，不因调用次数或文件数量限制而中断必要排障。
- 可用脚本、入口、依赖与触发方式维护在 [Shell 脚本与入口清单](../docs/shell.md)；优先复用现有入口，新增或删除脚本时同步更新。

提交或审查 PR 时，阅读 [贡献与 PR 规范](../../.github/CONTRIBUTING.md)。

## 编码原则

- 除非必要，勿增实体
- PaperRss对标业界最佳实践，参考netnewsware、freshRSS等优秀的开源实践
- 验证工具与自主决策原则：仓库提供了部分验证能力，Agent 应根据实际改动性质、风险与上下文自主权衡并决定执行策略，避免机械式跑全套流程，按需启用[自动化测试与分级验证矩阵](../docs/verification-matrix.md)。
- 发布全链路与 Release 门禁：遵守 SemVer（正式版 `vX.Y.Z`，预发布 `vX.Y.Z-beta.N`）；Beta 版本通过必要自动化用例后即可按授权发布，UI 验证由用户人工完成，Agent 不主动执行或等待 UI 验收；稳定版仍须先完成受影响路径的真实交互验收。详见 [发布流程与质量门禁](../docs/release-process.md)。

## 工程边界

- 扩大平台、改变产品或隐私行为、引入依赖以及执行发布前，必须有明确授权；已在本次任务中授权的操作不重复询问。
- 持久化变更兼容旧数据，阅读数据、模型配置等默认留在本地。修改源码、使用临时 fixture 或隔离测试库按任务授权执行；写入或迁移真实用户数据、启动可能自动迁移或持久化的真实 App / GUI 前，确认既有任务授权并按 [开发数据备份](../docs/dev-data-backup.md) 取得一致快照。已授权且能保证只读的检查无需备份；无法证明只读时按可能写入处理。
- API 密钥只经现有凭据入口读写，不注入 Prompt，不进入日志、导出或同步数据；仓库不保存秘密、PII 或私有基础设施信息。
- `PaperRss/Sources/Core/` 承担模型、解析、持久化、网络、同步、AI 和纯策略；新增代码不引入 SwiftUI、AppKit 或 UIKit。`I18N.swift` 与 `AppStore.swift` 当前已有 SwiftUI 依赖，属于现存过渡例外，不为满足此规则扩展本轮任务做架构搬迁。
- `PaperRss/Sources/App/` 承担 SwiftUI、应用生命周期和系统桥接，依赖方向固定为 App → Core。
- 修改 `ArticleReaderView` 的 JavaScript Bridge 时，同步核对 macOS/iOS Coordinator、消息协议与行为测试。
- 官网保持原生；`website/` 是唯一发布源码，i18n页面同步维护
- UI 文案进入 String Catalog 或现有本地化入口；i18n结构同步，语言切换即时且不改变 AI 输出设置。

## 业务边界

- macOS 是主要体验；未开启ios计划时，不考虑ios功能范围
